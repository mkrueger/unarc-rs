# T64 (C64S Tape Image) Format

## Overview

T64 is the tape container of Miha Peternel's C64S emulator. Despite its name it
is not a recording of a tape but a simple archive: a 64-byte header, a
directory of 32-byte records and the file data. All values are little endian.

## Header (64 bytes)

| Offset | Size | Description |
|--------|------|-------------|
| 0x00 | 32 | Signature, e.g. `C64S tape image file`, `C64S tape file` or `C64 tape image file`, padded with `$00` |
| 0x20 | 2 | Version (`$0100` or `$0101`) |
| 0x22 | 2 | Maximum number of directory entries |
| 0x24 | 2 | Number of used entries |
| 0x28 | 24 | Tape name, padded with spaces |

## Directory record (32 bytes)

| Offset | Size | Description |
|--------|------|-------------|
| 0x00 | 1 | Entry type: 0 = free, 1 = normal file, 3 = memory snapshot |
| 0x01 | 1 | 1541 file type (`$82` PRG, `$81` SEQ, ...); often just 1 |
| 0x02 | 2 | Start (load) address |
| 0x04 | 2 | End address (exclusive) |
| 0x08 | 4 | Offset of the file data in the image |
| 0x10 | 16 | File name, PETSCII, padded with spaces |

The file data does not include the two-byte load address; it is stored in the
directory record instead.

## Implementation notes

- **Detection.** The signature must start with `C64 ` or `C64S` and contain
  `tape`. This accepts the known variants and rejects TAP files (raw tape
  recordings, `C64-TAPE-RAW`) and cartridge images (`C64 CARTRIDGE`).
- **Directory.** Many images have wrong entry counts, so all records up to the
  larger of the two counts are read, stopping at the end of the file or at the
  first file data. Records with entry type 0 are skipped.
- **File sizes.** The end address cannot be trusted: CONV64 wrote `$C3C6` for
  every file. As in VICE, the stored size of a file is the distance from its
  data offset to the next larger data offset in the directory. The last file
  ends at the end of the image, or earlier if its address range is smaller
  (some images have trailing garbage). Sizes are capped to the 64 KiB address
  space. A truncated image therefore shortens its last file. A data offset
  outside the image fails with `ArchiveError::CorruptedEntry` when read.
- **Contents.** Every entry is extracted with its load address prepended, so
  PRG entries are standard `.prg` files. This is also done for SEQ/USR entries,
  as cbmconvert does, because T64 tools store the first two bytes of any file
  in the start address field.
- **Types.** `$80`/`$81`/`$83` (with bits 4-6 ignored) are DEL, SEQ and USR;
  every other value is treated as PRG, which is how C64S and VICE load them.
- **Names.** Trailing spaces are padding and removed; see
  [D64 entry names](d64.md#entry-names) for the conversion and extensions.

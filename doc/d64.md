# D64 (Commodore 1541 Disk Image) Format

## Overview

A D64 file is a sector-by-sector dump of a Commodore 1541 floppy disk. It has no
header and no signature. The disk uses zone bit recording, so the number of
256-byte sectors per track depends on the track:

| Tracks | Sectors per track |
|--------|-------------------|
| 1-17   | 21 |
| 18-24  | 19 |
| 25-30  | 18 |
| 31-42  | 17 |

Sectors are stored in order: track 1 sector 0, track 1 sector 1, and so on.

### Image sizes

| Tracks | Sectors | Size | Size with error bytes |
|--------|---------|------|-----------------------|
| 35 | 683 | 174848 | 175531 |
| 40 | 768 | 196608 | 197376 |
| 42 | 802 | 205312 | 206114 |

Images "with error bytes" append one byte per sector holding the read error
code of that sector, used to preserve copy protection. These bytes are ignored.

## Sector chains

Files and the directory are chains of sectors. The first two bytes of each
sector link to the next one (track, sector). In the last sector the track byte
is 0 and the second byte is the index of the last used byte, so the sector
holds `link - 1` data bytes at offsets 2 and up. Every other sector holds 254
data bytes.

## BAM (track 18, sector 0)

| Offset | Size | Description |
|--------|------|-------------|
| 0x00 | 2 | Link to the first directory sector (not used, see below) |
| 0x02 | 1 | DOS version, `$41` (`A`) |
| 0x04 | 140 | Block availability map: 4 bytes per track 1-35 |
| 0x90 | 16 | Disk name, PETSCII, padded with `$A0` |
| 0xA2 | 2 | Disk ID |
| 0xA5 | 2 | DOS type, usually `2A` |

Each BAM entry holds the number of free sectors of the track, followed by a
3-byte little-endian bitmap with a set bit for every free sector.

## Directory

The directory always starts at track 18, sector 1, whatever the BAM link says,
and is followed like a file chain (normally 18/1, 18/4, 18/7, ...). Each
directory sector holds eight 32-byte entries; the first two bytes of the
sector are the chain link.

| Offset | Size | Description |
|--------|------|-------------|
| 0x02 | 1 | File type: bit 7 closed, bit 6 locked, bits 0-2 type (0 DEL, 1 SEQ, 2 PRG, 3 USR, 4 REL); `$00` = scratched |
| 0x03 | 2 | Track/sector of the first data sector |
| 0x05 | 16 | File name, PETSCII, padded with `$A0` |
| 0x15 | 2 | REL: track/sector of the first side sector |
| 0x17 | 1 | REL: record length |
| 0x1E | 2 | File size in sectors, little endian |

## Implementation notes

- **Detection.** `ArchiveFormat::detect_from_reader` (and `detect`) recognise a
  D64 by its exact size and a plausible BAM: the free count of each of the
  tracks 1-35 must equal the number of free bits in its bitmap, the DOS version
  must be `A` or the DOS type `2A`, and the link in 18/1 must be valid. A random
  file of a D64 size passes this with negligible probability. Images whose BAM
  was edited (for example faked "blocks free" counts) are still opened through
  the `.d64` extension; a `.d64` path with a D64 size is treated as D64 even if
  the first sector looks like another format.
- **Entries.** All non-scratched directory entries are returned, including
  unclosed ("splat") files and DEL entries used as separators. File sizes come
  from following the sector chain; the directory block count is not trusted.
  An empty file (one sector with link `0/1`) has 0 bytes. Directory art, such
  as separator lines, usually points at the BAM (18/0); such an entry has
  0 bytes rather than the BAM and directory sectors its link leads through.
- **Error bytes.** The per-sector error table of 175531- and 197376-byte images
  is not consulted: sectors are read as they are stored. c1541 instead stops a
  file at the first sector the table marks bad.
- **Contents.** A file is the concatenation of its chain's data bytes, so PRG
  files start with their load address, as on disk. REL files yield their record
  data (the side sectors are not part of the chain). GEOS VLIR files are not
  interpreted; only the chain starting at the directory entry is returned.
- **Damaged images.** The image is read into memory when opened. Every chain
  walk visits each sector at most once. A file chain that leaves the disk or
  loops fails with `ArchiveError::CorruptedEntry` when the file is read; the
  listing ends at the first invalid or repeated directory link and returns the
  entries found so far.
- **Names.** See [Entry names](#entry-names).

## Entry names

D64, T64 and Lynx entries share one naming scheme: `NAME.ext`.

- `NAME` is the PETSCII name up to the first `$A0`. A name containing shifted
  letters (`$61`-`$7A`, `$C1`-`$DA`) was typed in the lower/upper case
  character set, so `$41`-`$5A` become lower case and the shifted letters upper
  case; otherwise `$41`-`$5A` stay upper case. This shows names the way the C64
  displays them (`HELLO`, but `Hello` for a name typed with shift).
- `£`, `↑` and `←` (`$5C`, `$5E`, `$5F`) map to their Unicode equivalents;
  graphics characters, control codes and `/` become `_`, so names never
  contain `/` or `\`. An empty name becomes `_`.
- `ext` is the lower-case CBM type: `prg`, `seq`, `usr`, `rel` or `del`
  (`cbm` for type values 5-7, which are invalid on a 1541).

The extensions follow cbmconvert's native output and common exporters. VICE's
`c1541 extract` writes the name without an extension and always in its
lower/upper case conversion (`hello`); cbmconvert writes `hello.prg` with the
same conversion and encodes REL record lengths in the extension (`.l20`).
Duplicate names are not made unique.
